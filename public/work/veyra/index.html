The problem

A marketplace is several products at once: discovery for buyers, setup and payouts for sellers, checkout, and delivery. The work was making them feel like one product.

What I built

I am responsible for the whole product: the design, the front end, the database and the payment and delivery logic. There is no backend team, which shapes most of the decisions below.

  • Buyer and seller account types, each with its own onboarding
  • A seller dashboard and storefronts for managing products
  • Free, Gold and Elite seller membership tiers
  • Buy Now purchasing and checkout with Paystack
  • A responsive layout for phones and desktops
  • Supabase migrations and row-level security policies for the data model

Decisions and reasons

  1. Supabase for data, authentication and access rules

    Supabase bundles Postgres, authentication and row-level security in one place. For a solo build that beats wiring an auth provider to a separate database layer, and the access rules live next to the data they protect.

  2. Paystack, with the commission kept out of shipping

    Payments run through Paystack, with bank and payout verification for sellers. The platform commission applies to product revenue only, never to shipping.

  3. Shipping worked out from distance

    Delivery cost depends on how far an order travels. I am moving shipping to a calculation at checkout, using OSRM for distance, instead of a flat fee shown in the cart. This is in progress.
